## 3. 数据与仿真器

**真实数据。** 从 Parkopedia 采集的 1,104 条停车报价，覆盖华盛顿州 Bellevue 的
**24 个车库**、**53 个时间快照**（2026-03-20 至 03-21）。价格区间 \$4.49–\$37.10，
中位数 \$8.74。

此外我从数据里提取了一个并非显式字段的信号：某个车库在某个快照中没有返回报价，最合理的
解释是当时**已订满**。因此每个车库的出现率（17/53 到 53/53 不等）构成了"该车库平时有多
紧俏"的真实数据代理。

**合成字段——公开说明而非隐藏。** 该数据源不含容量、坐标与 EV 标记。这些字段由车库 ID
确定性派生，并在 `data_provenance.md` 中逐字段列明。这是一项真实的局限，已写入有效性威胁
表，而不是一笔带过。

**仿真器。** 每个 episode 是一个 3 小时高峰窗口，请求按 Poisson 过程到达，各自带有异质的
停车时长、行程价值、价格敏感度、步行容忍距离与 EV 需求。每个车位被建模为 capacity 条
"车道"并施加区间调度约束——这是该领域真正的硬约束（同一个物理车位不可能被重复占用）。
场景生成完全种子化、跨实验臂逐位一致，构成**配对设计**。

## 4. Experiment B —— 动态定价（已完成）

**设计。** 分配器固定为 Greedy，**只有价格在变**。共 270 个 episode（3 个策略 × 3 个
负载水平 × 30 个种子）。

| 策略 | 定义 |
|---|---|
| P0 静态 | CSV 真实价格，不作调整 |
| P1 规则加价 | 争抢中的车位 ×1.5 —— CampusPark 的生产规则（`server.js:574`），改写为尺度无关形式 |
| P2 置换对照 | 施加与 P1 在同一窗口内**数量完全相同**的 ×1.5 加价，但随机撒到其他车位上 |

**为什么用 P2 而不是"同均值的随机乘数"。** 我最初的方案里对照组写的是 U[1.0, 1.5]，
理由是它与 P1 同均值。但这并不成立：U[1.0, 1.5] 的均值是 1.25，只有当加价规则恰好 50%
触发时两者才同均值，而触发率是未知的。改为**复用 P1 实际的加价次数、只随机置换其位置**
之后，边际价格分布在**任何触发率下都按构造完全一致**（实测两组平均乘数 1.144 vs 1.143），
唯一的变量就只剩"有没有瞄准争抢车位"。

### 4.1 结果一：生产规则降低了车位利用率

利用率是本实验预先声明的主指标。结果与我的假设方向相反。

| ρ | 利用率变化（P1 vs P0） | Cohen's d | p |
|---|---|---|---|
| 0.8 | −1.31% | −1.24 | 1.8e−07 |
| 1.2 | −1.02% | −1.02 | 4.7e−06 |
| 2.0 | **−3.79%** | −4.09 | 2.9e−18 |

且争抢越严重，损失越大。这条规则更准确的描述是"**用利用率换收入**"，而不是一种提效手段。

![图 1：Experiment B 的利用率与收入](llm-allocation-study/results/figures/fig1_pricing.svg)

**图 1.** 加价规则在所有负载下都降低利用率，换来收入。两个度量画成两个面板而非双纵轴。


### 4.2 结果二：收入增长来自"瞄准"，而非涨价本身

在平均价格乘数相同的前提下，把加价瞄准争抢车位比随机撒出去**多赚 5.94%**
（ρ=2.0，d=+3.98，p=1.6e−19）。如果没有 P2 这个对照，自然的解读会是"动态定价提升收入
6%"，并把功劳记在涨价上。

### 4.3 一条我报告过、随后又自己推翻的结论

我起初把第三条结果视为最锐利的发现：不瞄准的涨价赚不到钱——P2 平均多收 13.8% 的价格，
收入反而**下降 0.78%**（p=0.008）。

由于价格敏感度是一个**设定的、未经实测的**参数，我执行了自己 proposal 的有效性威胁表里
要求的敏感性扫描：5 档设定，**同时变动敏感度的"水平"与"离散度"**，并保证其余全部请求属性
逐位不变。

| 结论 | 一致档数 | 处理 |
|---|---|---|
| 加价降低利用率 | **5/5**，且量级随弹性单调变化 | 可无条件报告 |
| 瞄准优于同价随机加价 | 4/5 | **带边界条件**报告（在"高敏感且同质"人群下失效） |
| 不瞄准的涨价赚不到钱 | **2/5，符号翻转** | **降级**为"基线假设下的观察"，不作为结论 |

其机制是可解释的：**水平**决定涨价会损失多少交易量，**离散度**决定还能否从价格不敏感的
那条尾巴上榨取剩余。在**相同的平均弹性 2.0** 下，同质人群亏 2.14%，而高度异质的人群反而
赚 0.77%。基线设定恰好落在符号翻转点附近。

要坐实这一条，需要的是 CampusPark 的**真实价格弹性数据**（不同价位下的转化率），而不是
更多仿真。我已在所有出现过该结论的地方作了更正。

![图 2：敏感性扫描中的符号翻转](llm-allocation-study/results/figures/fig2_sensitivity.svg)

**图 2.** 我自己推翻的那条结论。同一个对照在 5 档弹性设定下有 3 档符号翻转；注意最后两行——**平均弹性相同（2.0）**，同质人群亏 2.14%，高度异质的人群反而赚 0.77%。

## 5. Experiment A —— 设计已冻结，待执行

完整预注册文档见 `PRE_REGISTRATION.md`，**写于任何一次 LLM API 调用之前**。

**实验臂。** B0 Random（下界）· B1 FIFO（对应生产环境的原子预订事务）· B2 Greedy
（强在线基线）· T1 LLM 单轮中央分配器（**消融组**——用于把"推理"与"协商"两个变量分开）
· T2 LLM 三轮多智能体协商（处理组）。

**配置。** 车队缩放至 240 个车位；ρ ∈ {0.8, 1.2, 2.0}（对应 192/288/480 个请求）；
主网格 n=60 个种子，effort 消融 n=20；broker 用 Claude Opus 5，每用户 agent 用
Claude Haiku 4.5；全程使用 strict JSON schema 约束工具调用。

**预注册中作出的承诺。**
- 主指标事先固定：成功率、Jain's 公平性指数。次要指标族单独做 Holm–Bonferroni 校正。
- **为每条假设写明了证伪标准**，其中特别包括：不显著**不等于**等价——若置信区间跨越
  ±MDE，结论必须逐个负载水平记为"检验力不足以判定"，不得写成"无显著差异"。
- 停止规则：不中途看结果、不因结果不理想追加种子、不重跑失败的 episode、不修补非法分配。
- **记录了全部 prompt 与工具 schema 的 SHA-256 指纹**，使"事后调 prompt"成为可被检测的行为。

**冻结配置下的实测检验力**（经典臂已在该配置下跑完 540 个 episode）：

| 指标 | ρ=0.8 | ρ=1.2 | ρ=2.0 |
|---|---|---|---|
| 成功率 MDE | 0.95 pp | 0.80 pp | 0.63 pp |
| Jain's 指数 MDE | 0.80 pp | 0.58 pp | 0.52 pp |

配对设计使方差下降约 74%。这些数字来自确定性策略，只包含场景方差；LLM 臂会叠加模型自身
随机性，因此在正式采信主网格之前，会先用 pilot 数据重算检验力。

## 6. 从研究到可部署系统

研究如果只停在"哪个策略指标更好"，就漏掉了一个更实际的问题：**假设 H3 说 LLM 会产出传统
调度器结构上不可能产出的分配**（幻觉车位、重复占位、EV 错配）。一个信任模型输出的系统，
会真的把同一个物理车位卖给两个人。因此我把研究结论落成了一层可部署的工程实现。

### 6.1 一个必须处理的矛盾

预注册 §5 明令**禁止**重试失败的 episode、**禁止**修补非法分配——因为两者都会抹掉这项研究
要测量的失败模式。而生产环境的义务恰恰相反：它必须重试、必须兜底、必须保证用户拿到答案。

这两个要求无法在同一份代码里同时成立。因此 `serving/` 层**只包装、不修改**
`harness/policies/`：研究路径与预注册逐字一致，生产路径在其外侧获得安全网。

### 6.2 分层结构

```
请求
  → 成本上限闸        超出预算直接拒绝走模型
  → 熔断器            模型连续失败时彻底跳过，不再持续烧钱
  → 截止时间 + 有界重试
  → LLM 策略          harness/，原封不动
  → 校验闸            用与实验完全相同的 validator；非法分配一律丢弃，绝不修补
  → Greedy 兜底       把模型丢掉的请求重新分配一遍
  → 遥测              延迟 p50/p95、成本、非法率、降级率
```

服务用标准库实现（无框架），与 CampusPark 自身的 `server.js` 风格一致。在**没有 API key**
的环境下实测行为：`/healthz` 返回 503 并明确报告 `status=degraded, breaker=open`，
`/allocate` 仍然返回可用结果（走 Greedy）并标注 `degraded=true`。**降级而非崩溃，且诚实
汇报自己处于降级状态。**

### 6.3 测试与 CI

75 个测试全部使用桩客户端，且 `conftest.py` 会**硬阻断对外网络连接**——一个不慎开始调用
真实 API 的测试会让每次 push 都产生费用，所以从机制上让它不可能发生，而不只是靠约定。

CI 在无 API key 的环境下检查五件事：测试通过、**两次独立运行结果逐位一致**、经典策略零非法
分配、**prompt 指纹仍与预注册一致**（使"事后调 prompt"成为可检测行为）、以及服务在无 key
时优雅降级。

### 6.4 工程层自身也抓到了两个 bug

**（a）超时形同虚设。** `with ThreadPoolExecutor(...)` 在退出时会调用 `shutdown(wait=True)`，
阻塞等待那个卡住的线程结束——超时被正确检测到了，但调用方仍然等满了 5 秒。测试直接断言
"调用方不得等待卡死的模型"并捕获了它（断言 <3s，实测 5.02s）。这类缺陷上线即事故。

**（b）CI 的可复现性检查是我自己写错的。** 直接 `diff` 两个结果 CSV 必然失败，因为
`decision_latency_s` 是墙钟时间。在本地先执行了一遍 CI 步骤才发现，否则每次 push 都会红。

### 6.5 低成本 pilot

在投入约 \$748 的全网格之前，先花约 **\$6** 分四步验证，每一步都写明"发现什么就停下来"：
API 链路是否通（\$0.02）、成本估算精度与非法分配率量级（\$1）、**协商修正轮是否真的跑满**
（\$1.8）、模型自身方差是否让 n=60 的检验力失效（\$3）。最后一项尤其重要：若模型抖动与
经典臂的配对差 SD 相当，则冻结的 MDE 偏乐观，此时**不能偷偷追加种子**（预注册禁止），
必须回去修订样本量、记录理由并重新冻结。

## 7. 我认为值得说明的方法论要点

**在无法设定 `temperature` 的条件下保证可复现性。** 当前的 Claude 模型会直接拒绝
`temperature` 参数（HTTP 400），传统的"温度归零求确定性"做法已不可用。本设计没有回避这个
问题，而是把随机性**隔离并测量**：场景生成完全种子化，每个单元格重复三次，再用线性混合
效应模型做方差分解并报告组内相关系数（ICC），即"模型自身抖动占总方差的比例"。

**缩放验证，以及它证明不了什么。** LLM 臂无法在全尺寸下承担成本，因此供给与需求被同比
缩小（以保持 ρ 的原义）。在采信它之前，我把经典基线在两个尺度上分别跑了一遍：策略排序在
6/6 个（指标, ρ）单元格中全部保持，各格均值最大偏差 0.121。**但我起初对这个结果过度解读
了**：它验证的是效应**量级与排序**，不是统计**精度**。实测 MDE 在小尺度下是 2.57 pp，
全尺寸下是 0.79 pp——这正是最终冻结配置采用了比原计划更大车队的原因。

![图 3：两个尺度的缩放验证](llm-allocation-study/results/figures/fig3_scale.svg)

**图 3.** 缩放保住了策略排序（6/6 单元格），各格均值最大偏差 0.121。

![图 4：可检出效应量随车队规模变化](llm-allocation-study/results/figures/fig4_mde.svg)

**图 4.** 但精度没保住。这是对我此前说法的更正：图 3 验证的是量级与排序，不是统计精度。


**失败模式被测量，而不是被修补。** 一个独立的校验器会对每一次分配重新核验硬约束。LLM
输出的非法分配会被记录并拒绝，绝不修补——修补它恰好会抹掉假设 H3 想要测量的那个量。

**两个在污染结果之前被抓到的 bug。**（a）LLM 的提交路径没有执行经典策略同样施加的验收
阈值，这会导致一个负效用的匹配在 LLM 臂里被计为"成功"，使成功率在不同条件之间不可比。
（b）一处工具名不匹配，导致 T2 的协商修正轮**每次都静默失效**。两者都是通过一个使用桩
客户端的零成本干跑测试发现的，发生在花掉任何一分钱之前。

**成本推理被实测修正。** 离线剖析显示开销几乎完全由 broker 的推理 token 主导（同一网格
在不同思考预算下相差 11.7 倍，\$26–\$303），而我 proposal 中着重讨论的 agent 模型选择
仅占 1.4–2.4%。因此推理 effort 被当作**实验因子**处理（更深的推理是否换来更好的分配？），
而不仅仅是一个成本旋钮。

   还是必须有真实用户交互数据？诚实的局限是：24 个车库、约 24.5 小时，且容量/地理/EV
   字段为合成。
2. **关于 §4.3 被推翻的那条结论。** 我倾向于把它作为敏感性分析结果**显著地报告出来**，
   而不是删掉——因为其机制本身有意思，而且这段经历正好体现了对照组设计的价值。
   您认为应该放在正文结果里，还是附录？
3. **样本量。** 每格 n=60（经典臂上 MDE 约 0.5–0.95 pp）是否可接受？考虑到 LLM 臂的噪声
   会更大一些。
4. **Experiment A 的范围。** effort 消融（更深的推理是否提升分配质量）是否应保留在范围内？

5. **是否加入真人被试。** 做一个小规模研究，考察用户**主观感知**的公平性是否与 Jain's
